# GenomicDataProcessing

Teaching materials for **Genomic Data Processing**, a visiting lecture in
*Data Processing for Big Science*.

Junseok Park, PhD · Baylor College of Medicine

## Contents

### [`day1-coordination/`](day1-coordination) — Day 1 (10/12): coordinates, evidence, reproducible workflows

The hands-on package for the Day 1 practice session. A collaborator sends results processed
on **hg19 (GRCh37)**; the analysis environment runs on **hg38 (GRCh38)**. Both files say
`chr11`, and the numbers in them do not mean the same thing. Students establish the
reference, convert deliberately, verify against an independently documented coordinate, and
report what failed.

```bash
cd day1-coordination
jupyter lab genomic_data_processing_practice.ipynb
```

Requires Python 3.9+ and `pandas`. `pysam` and IGV are optional — every BAM ships with a
`.sam` text twin and the IGV session files are generated by the notebook. No network access,
no reference download, no aligner index build; every cell runs in seconds.

See [`day1-coordination/README.md`](day1-coordination/README.md) for the full file inventory,
the slide-to-section mapping, and the list of deliberate failures students are expected to
handle rather than fix.

### [`day2-3-samples/`](day2-3-samples) — Day 2 (10/13): what is a genomics sample?

Two 15-minute mini practices for the Day 2 lecture *Molecular tools for genomics*. One message
runs through both: a genomics sample is **specimen + molecule + metadata**, and every file
downstream inherits all three.

* **Mini practice 1 · Is this sample fit for this platform?**
  (`practice1_sample_to_platform.ipynb`) — twelve tubes (blood, saliva, buccal swab, FFPE and
  fresh-frozen tumour, plasma cfDNA, a cell line, RNA) are checked against Illumina, PacBio HiFi
  and Oxford Nanopore input requirements and marked PASS / REVIEW / FAIL / BLOCKED with a written
  reason. Part B compares simulated reads from the three platforms over the real hg38 β-globin
  window from Day 1: read length, N50, accuracy, and how many reads span an 8-kb target.
* **Mini practice 2 · Cohort QC: who does not belong?** (`practice2_cohort_qc.ipynb`) — a
  synthetic 2,000-exome cohort is taken through the quality-control steps of the UK Biobank exome
  study (Wang et al., *Nature* 2021): consent, contamination, coverage, sex and array checks,
  duplicates and relatives, ancestry and batch. Students find the planted cases and rebuild the
  QC funnel.

```bash
cd day2-3-samples
python -m pip install -r requirements.txt
jupyter lab
```

Requires Python 3.9+ with `pandas`, `numpy` and `matplotlib`. No network access, no aligner and
no reference download; each notebook runs top to bottom in a few seconds. See
[`day2-3-samples/README.md`](day2-3-samples/README.md) for the expected answers, the planted
cases, the slide-to-notebook mapping and instructor notes.

### [`day4-VariantCalling/`](day4-VariantCalling) — Day 4 (10/15): understanding genetic variants

Two 75-minute practices for the Day 4 lecture *Understanding genetic variants*. Both start from raw
reads of synthetic people at real genomic loci, and every step ends with a check of what changed.

* **Practice 1 · From reads to variants** (`practice1_variant_calling/`) — a child with sickle cell
  disease and two healthy parents, on the real GRCh38 β-globin window used on Days 1 and 2. The steps
  are read QC, alignment, duplicate marking, coverage, genotype likelihoods worked by hand, joint
  calling, normalisation, filtering, benchmarking against the planted truth and trio checks. Students
  end with the HGVS name NM_000518.5(HBB):c.20A>T p.(Glu7Val).
* **Practice 2 · CNVs from reads to interpretation** (`practice2_cnv_tesseract/`) — three referred
  patients. CNVs are called from read depth on hg19, lifted to hg38 and checked, then tested in matched
  (synthetic) RNA. Students prepare the TESSERACT-CNV input and discuss each CNV with public ClinGen,
  ClinVar, gnomAD and conservation tracks.

```bash
cd day4-VariantCalling
conda env create -f environment.yml && conda activate d4-practice
cd practice1_variant_calling && jupyter lab
```

Requires conda (Miniforge) on macOS or Linux, or WSL2 on Windows. samtools, bcftools, minimap2,
fastp, CrossMap and pysam come from bioconda. Each notebook runs within a few minutes, and no network
access is needed except for two optional steps. See
[`day4-VariantCalling/README.md`](day4-VariantCalling/README.md) for the slide-to-notebook mapping,
the TESSERACT-CNV adapter and where the answers are.

### [`day5-visualization/`](day5-visualization) — Day 5 (10/27): data visualization in genetics and genomics

A 90-minute practice in pairs for the Day 5 lecture *Data visualization in genetics and genomics*. Students start with
small tables they can read by eye, then move to realistic simulated data: they run the test or method a real analysis
would use, check the result against the planted answer, and only then draw the figure
(Question → Test → Check → Visualize).

* **Core for everyone** (`practice.ipynb`) — diagnose eight misleading figures; make simple figures from small tables
  (Anscombe's quartet, mapping rates, one gene in two groups, cell-type composition, a time course, 60,000 CpGs); B1 compares
  two groups with n = 4 and n = 40 per group; B2 takes bulk RNA-seq of dexamethasone-treated airway smooth-muscle cells from
  counts to a volcano plot, with a sequencing batch to handle.
* **One elective per pair** (`electives/`) — GWAS with ancestry stratification, single-cell embeddings, copy number at
  22q11.2, a variant-caller benchmark, classifier evaluation at 3.5% prevalence, and a TP53 lollipop plot.

```bash
cd day5-visualization
conda env create -f environment.yml && conda activate dataviz-practice
cd dataviz_practice && jupyter lab
```

Requires Python 3.11+ with numpy, pandas, scipy, matplotlib, scikit-learn, umap-learn and adjustText (or
`pip install -r dataviz_practice/requirements.txt`). No network access is needed; the core notebook runs in about
10 seconds and each elective in under a minute. See [`day5-visualization/README.md`](day5-visualization/README.md)
for the slide-to-notebook mapping, the timing and where the answers are.

## Real data vs teaching data

The `chr11` sequence in both mini-references is genuine UCSC sequence, the gene models are
NCBI RefSeq Select transcripts, and the hg19 ↔ hg38 checkpoint correspondence is documented
in ClinVar. Everything else — samples, reads, genotypes, depths, the `toy1` contig and the
chain file — is synthetic teaching material and is labelled as such throughout.

Day 2 reuses the same real hg38 β-globin window and gene models. Its sample sheet, reads, cohort
and QC metrics are synthetic; the platform input requirements come from vendor documentation and
the cohort QC thresholds from Wang et al. (2021), each with its source recorded in the package.

Day 4 uses real GRCh38 and hg19 sequence, gene models, the UCSC liftover chain and public annotation
tracks (ClinGen, ClinVar, gnomAD, DGV, ENCODE), each with its provenance recorded in the package. The
CNVs sit at public ClinVar and LOVD loci so that they can be checked against real records. The people,
phenotypes, reads, genotypes and RNA counts are synthetic, and the evidence tables are teaching
exercises, not classifications.

Day 5 builds every dataset on real anchors: hg38 chromosome lengths and MANE Select genes, glucocorticoid-response genes
reported by Himes et al. (2014), AMD loci reported by Fritsche et al. (2016), UCSC segmental duplications and the ClinGen
region ISCA-37446 at 22q11.2, the TP53 protein (UniProt P04637) and Anscombe's published quartet. The counts, genotypes,
cells, scores and variant calls are synthetic, each generated with a fixed seed and a planted answer, so that every
figure can be checked against the truth.

**No output of these materials is a clinical result.** A public variant site is used for its
coordinates only, because those coordinates are documented on both assemblies.

## Reproducing the data package

Day 1:

```bash
cd day1-coordination/build
python build_lab.py      # writes the data files (requires pysam)
python make_notebook.py  # writes the notebook
```

The only network calls are two UCSC sequence fetches, already cached in `build/lab_src/`.

Day 2:

```bash
cd day2-3-samples
python build/build_practice1.py && python build/build_practice2.py   # data and checkpoints
python build/make_notebooks.py                                       # the two notebooks
python build/verify_package.py                                       # runs both notebooks and checks every answer
python build/check_slide_refs.py <Day 2 deck .pptx>                  # slide citations vs the deck
```

Day 2 needs no network at all; the real β-globin window is shipped in `data/practice1/`.

Day 4:

```bash
cd day4-VariantCalling/practice1_variant_calling
python scripts/generate_data.py      # rebuilds data/ from the saved UCSC downloads (seed 20261015)
cd ../practice2_cnv_tesseract
bash scripts/make_all.sh             # re-downloads the public inputs and rebuilds the synthetic data
```

Day 5:

```bash
cd day5-visualization/dataviz_practice
bash build/make_data.sh              # rebuilds data/ byte for byte (fixed seeds; needs pydeseq2)
```

The notebook builders and the lecture-figure scripts are described in
[`day5-visualization/dataviz_practice/build/README.md`](day5-visualization/dataviz_practice/build/README.md).
